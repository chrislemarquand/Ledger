# v1.4 Manual Smoke Checklist

Phase 6's manual gate (`v1.4-performance-audit-plan.md`): "one-frame
flashes, animation quality, menu timing, and native AppKit feel; keyboard
navigation, responder chain, standard shortcuts, and menu ordering; Reduce
Motion and accessibility behaviour on touched surfaces; macOS 26 and 27
chrome/window behaviour; external-volume disconnect and iCloud-placeholder
behaviour; real EOS-1V camera and ES-E1 cable smoke where touched code
could interact; any framework log correlated with a visible failure during
automation." This is that gate, turned into a concrete pass/fail list
against what v1.4 actually changed — each item names the phase/fix it
verifies, not a generic regression sweep.

Use a Release build (`Product > Archive` or the `run_benchmarks.sh` build,
not a Debug/Xcode-run build — chrome and animation timing can differ under
the debugger). Check items off live; note anything unexpected inline
rather than waiting until the end.

Not covered here: automated-gate items (build/tests, benchmarks, hitch
traces) — those are done, see `v1.4-progress.md`'s Phase 6 section.

## 5. UI/HIG polish pass (this session, `47e3a83`)

- [x] PASS — Destructive buttons (Delete in Lens/Preset managers) render in red,
      not accent colour. Found and fixed two real bugs during this pass:
      both used `role: .destructive` + `.buttonStyle(.borderedProminent)` +
      a manual `.tint(.red)`, which rendered as a bright flat red instead of
      native muted red. macOS has no "filled prominent destructive" system
      style — `role: .destructive` only renders natively inside `.alert()`/
      `.confirmationDialog()` (deferring to NSAlert's own button chrome);
      a free-standing `Button` gets zero automatic color from role alone,
      confirmed empirically (tried `.bordered` + role only first — no red
      at all). Fixed to `.buttonStyle(.bordered)` +
      `.tint(Color(nsColor: .systemRed))` in both `PresetSheets.swift` and
      `LensProfileSheets.swift` — muted/native-looking, confirmed visually.
      Same audit found the AppKit "Delete Backups" button in Settings has
      no visible destructive styling either (`contentTintColor` is a no-op
      on a plain-text push button; only `hasDestructiveAction` was kept,
      for its accessibility semantics) — user confirmed this matches other
      AppKit settings windows' convention and is fine as-is, not a bug.
      Also added `hasDestructiveAction` to the EOS-1V roll delete/restore
      toggle button (`EOS1VShootingViewController.swift`, untested — no
      camera connected this session), to the "Discard Changes" unsaved-
      edits alert (`AppModel+ApplyRestore.swift`, untested this pass), and
      to the "Quit and Discard" button on the quit-with-unsaved-changes
      alert (`LedgerApp.swift:288`) — found via a full audit of every
      `NSAlert()` call site in the app for missed destructive confirmations
      (18 sites checked; "Apply changes"/"Apply preset" alerts deliberately
      left alone — they write to disk irreversibly but are the primary
      expected action, not an accidental-loss risk, matching existing
      app convention).
- [x] PASS — Every other button in Set Location, Date/Time Adjust, Manage
      Presets, and the Preset Editor renders neutral grey, not a faint
      teal tint (the ambient-`.tint()` bug). Note: Manage Presets' "Done"
      button is intentionally plain/grey (no `.buttonStyle`) since it only
      dismisses the sheet rather than performing an action.
- [x] PASS — Manage Presets / Manage Lenses sheets, and the Preset/Lens editors,
      match each other's layout, spacing, and title font.
- [x] PASS — Preset editor's Rating/Flag/Colour Label controls behave exactly
      like the Inspector's (star clicks, flag toggle, colour swatch menu).
- [x] PASS — Trigger each converted alert-to-inline-text case at least once:
      opening a pinned/recent folder that no longer exists; a Batch Rename
      pattern that changes nothing; exporting with a pending-edits warning
      present. Confirm the new inline/status text actually appears and
      reads correctly, not just that no alert pops up.
- [x] PASS — SF Symbol bounce effect on star rating, flag, Rotate, Flip, and Open
      — confirm it fires once per actual state change, not continuously
      or on unrelated re-renders.

## 8. External volume / iCloud disconnect

- [x] PASS — Open a folder on an external/removable volume, then disconnect it
      mid-browse (or mid-load, if you can time it). Confirm a sensible
      "folder unavailable" state, no crash, no indefinite spinner. **This
      is the one Phase 2.3 exit-gate criterion explicitly never exercised
      in any automated form this whole project** — first real check of it.
      Result: browser reverts cleanly to "no folder selected" state, with
      subtitle message "External source disconnected." No crash, no spinner.
      Follow-up testing (reconnect, then a real physical/surprise
      disconnect) found and fixed two further real bugs, not caught by
      the pass above since it only exercised a single disconnect: the
      disconnected status message never cleared on a later successful
      reopen, and the sidebar's volume row could survive a physical yank
      (sometimes relabelling to "Macintosh HD"). Full details and fixes in
      `v1.4-progress.md`'s Phase 6 manual-gate section. Both confirmed
      fixed via live retest with a real external drive.

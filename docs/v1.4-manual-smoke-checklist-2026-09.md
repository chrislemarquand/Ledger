# v1.4 Manual Smoke Checklist

Phase 6's manual gate (`v1.4-performance-audit-plan.md`): "one-frame
flashes, animation quality, menu timing, and native AppKit feel; keyboard
navigation, responder chain, standard shortcuts, and menu ordering; Reduce
Motion and accessibility behaviour on touched surfaces; macOS 26 and 27
chrome/window behaviour; external-volume disconnect and iCloud-placeholder
behaviour; real EOS-1V camera and ES-E1 cable smoke where touched code
could interact; any framework log correlated with a visible failure during
automation." This is that gate, turned into a concrete pass/fail list
against what v1.4 actually changed — each item names the phase/fix it
verifies, not a generic regression sweep.

Use a Release build (`Product > Archive` or the `run_benchmarks.sh` build,
not a Debug/Xcode-run build — chrome and animation timing can differ under
the debugger). Check items off live; note anything unexpected inline
rather than waiting until the end.

Not covered here: automated-gate items (build/tests, benchmarks, hitch
traces) — those are done, see `v1.4-progress.md`'s Phase 6 section.

---

## 1. Launch and menu bar (Phase 4.0/4.1)

- [ ] Menu bar (Apple/Ledger/File/Edit/View/Image/Folder/Window/Help) is
      fully present and populated **immediately** on launch — no visible
      gap where only "🍎 Ledger" shows before the rest fills in. Watch the
      first ~1s closely; this was the original menu-timing bug.
- [ ] Open Settings, then the ExifTool Console — menu bar stays correct
      and unaffected both times (these host SwiftUI content, the original
      regression trigger).
- [ ] Open Import, Batch Rename, and Date/Time Adjust sheets (also host
      SwiftUI) — menu bar still unaffected. **Not exercised by the
      original fix's live verification** — this is the one place it was
      flagged as still open.
- [ ] Standard Edit menu items (Undo/Redo/Cut/Copy/Paste/Select All, plus
      AutoFill/Start Dictation/Emoji & Symbols) work and are enabled
      appropriately.
- [ ] Window menu present with Minimize/Zoom/Bring All to Front and a live
      entry for the open window (this menu didn't exist pre-v1.4).
- [ ] Keyboard shortcuts fire correctly with no window ever opened yet
      (proves responder-chain routing, not a stale explicit target).

## 2. Window, split view, and list columns (Phase 4.2)

- [ ] Resize the main window across a wide range, including down to the
      point the toolbar's view-mode control collapses to an overflow
      button. List column widths track smoothly — no visible column
      "fighting" or snapping back.
- [ ] In List view, drag a column border to a custom width, then resize
      the window narrower and wider again. The dragged width should
      survive viewport changes, not silently reset.
- [ ] Quit and relaunch — window frame, split position, and any dragged
      list column width all restore correctly.
- [ ] Watch List view load a folder (especially with iCloud files still
      materializing) for a flickering horizontal scrollbar appearing/
      disappearing across frames — this was a live, reproducible bug
      before the native-first fix.
- [ ] Compare List view's column-fit behaviour side-by-side with Finder on
      the same folder — Name should absorb slack, other columns stay
      fixed, matching frame-for-frame.

## 3. Sidebar (Phase 4.3)

- [ ] Launch with a folder open and watch the sidebar's initial scroll
      position — no visible upward "snap" shortly after the window
      appears.
- [ ] Click between sidebar folders repeatedly — no accent-colour flash
      immediately reverting to grey on click.
- [ ] Click a sidebar folder, then click into the browser pane — sidebar
      selection dims to grey (matches Photos.app; this is correct native
      behaviour, not a bug to "fix" again).
- [ ] Window inactive (click another app) — sidebar selection label/icon/
      badge colours look correct, not stuck in an active-window state.
- [ ] List/Icon/Gallery selection highlight consistency: select an item,
      switch view modes, click away to defocus — accent/grey state should
      behave the same way across all three modes.

## 4. Browser surfaces, thumbnails, cloud (Phase 1.1–1.4, 3.3)

- [ ] Switch Icon → List → Gallery → Icon repeatedly on a real folder — no
      stale thumbnails, no flash of placeholder icons for already-warm
      thumbnails.
- [ ] Scroll a large folder (the 1,012-file benchmark corpus or similar)
      continuously — no visible hitch or stutter.
- [ ] Force a cold thumbnail cache (or use a very large/unvisited folder)
      and confirm cells still resolve to real thumbnails promptly, not
      stuck on placeholders.
- [ ] A file with an iCloud placeholder shows the correct cloud badge and
      does **not** trigger an implicit full download just from being
      visible/scrolled past.
- [ ] Select a file, then quickly select a different one before the first
      finishes loading its metadata/preview — inspector should show the
      second file's data, never a flash of stale data from the first.

## 5. UI/HIG polish pass (this session, `47e3a83`)

- [ ] Destructive buttons (Delete in Lens/Preset managers) render in red,
      not accent colour.
- [ ] Every other button in Set Location, Date/Time Adjust, Manage
      Presets, and the Preset Editor renders neutral grey, not a faint
      teal tint (the ambient-`.tint()` bug).
- [ ] Manage Presets / Manage Lenses sheets, and the Preset/Lens editors,
      match each other's layout, spacing, and title font.
- [ ] Preset editor's Rating/Flag/Colour Label controls behave exactly
      like the Inspector's (star clicks, flag toggle, colour swatch menu).
- [ ] Trigger each converted alert-to-inline-text case at least once:
      opening a pinned/recent folder that no longer exists; a Batch Rename
      pattern that changes nothing; exporting with a pending-edits warning
      present. Confirm the new inline/status text actually appears and
      reads correctly, not just that no alert pops up.
- [ ] SF Symbol bounce effect on star rating, flag, Rotate, Flip, and Open
      — confirm it fires once per actual state change, not continuously
      or on unrelated re-renders.

## 6. Keyboard, Reduce Motion, accessibility

- [ ] Full keyboard-only pass: open a folder, navigate the browser with
      arrow keys, change selection, open Inspector fields, and apply a
      metadata edit — all without touching the mouse.
- [ ] VoiceOver on for a few minutes in the browser and sidebar — items
      are announced sensibly, no silent/unlabeled controls encountered.
- [ ] System Settings → Accessibility → Reduce Motion on — check
      view-mode switches, sheet presentation, and the new SF Symbol bounce
      effects (§5) all respect it (bounce should not play, or should
      reduce, under Reduce Motion).

## 7. macOS 26 vs 27 chrome

- [ ] Run through §§1–3 once on macOS 26 if a 26 machine/VM is available —
      several Phase 4.3 items were macOS-27-specific ("moot now" findings
      that assumed 27's redesigned chrome). If only 27 is available, note
      that explicitly rather than silently skipping this.

## 8. External volume / iCloud disconnect

- [ ] Open a folder on an external/removable volume, then disconnect it
      mid-browse (or mid-load, if you can time it). Confirm a sensible
      "folder unavailable" state, no crash, no indefinite spinner. **This
      is the one Phase 2.3 exit-gate criterion explicitly never exercised
      in any automated form this whole project** — first real check of it.

## 9. EOS-1V camera / ES-E1 cable

- [ ] Connect a real EOS-1V via the ES-E1 cable. Device detection,
      shooting-data import, and roll/frame browsing all work.
- [ ] Trigger the CSV-parsing path touched in Phase 3.4 (a real
      film-roll/shooting-data import) — confirm parsed data looks correct,
      including any field containing a comma or embedded quote if your
      test rolls have one.
- [ ] EOS-1V clock-set sheet's "Adjust" button (part of §5's button-colour
      pass) renders and behaves correctly.

## 10. Log correlation

- [ ] Keep Console.app (filtered to the Ledger process) open during the
      whole pass. Any crash, fault, or repeated warning that lines up with
      something you saw on screen gets a line here, even if the UI itself
      "looked fine."

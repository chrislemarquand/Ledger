Use `~/Downloads/Ledger v1.3 Smoke Test/Gallery Browse/` (enough JPEGs to meaningfully browse).

✅ **4.1** Switch to Gallery mode (toolbar or View menu). Layout is filmstrip along the bottom, large
preview at top — a third mode distinct from icon and list.
✅ **4.2** Click through several filmstrip thumbnails — large preview updates correctly, no stale
image left over from the previous selection.
✅ **4.3** Arrow-key navigation moves through the filmstrip and updates the large preview.
Originally failed — arrow keys didn't move selection until a thumbnail was clicked first,
and Gallery didn't auto-select the first item on entering a folder (unlike Finder's own
Gallery/Column View). Fixed by three changes: `switchToIconAction`/`switchToListAction`/
`switchToGalleryAction` now call `focusBrowserPane()` after a view-mode switch;
`BrowserFilmstripViewController.renderState()` auto-selects the first item when Gallery is
active and nothing in the current folder is selected; and `AppModel.handleExplicitSidebarSelectionChange`
now posts `.browserDidRequestFocus` after navigating (sidebar/breadcrumb/Recents), since that
previously only fired at launch and on toolbar mode switches, not on folder navigation, so the
browser pane lost keyboard focus on every folder change. Re-verified: pass.
✅ **4.4** Switch freely between Icon / List / Gallery modes (toolbar and View menu both) — no
crashes, no leftover state from one mode bleeding into another.

✅ **8.1** In the ExifTool Console (Section 7) or via any Apply operation, confirm the bundled
ExifTool reports **13.55** (not 13.50) — e.g. the command line shown includes the app's bundled
`exiftool/bin/exiftool` path, and its behaviour/output matches 13.55 (check `exiftool -ver`
against the same binary path from Terminal if unsure). Verified directly (Claude): the
`SharedUI.xcworkspace` → `Ledger` scheme build is 13.55, correct — Chris confirmed this is the
one he runs. Note: a separately-cached `Ledger.xcodeproj`-opened-alone build was found stuck on
13.50 despite a same-day rebuild, because the "Bundle ExifTool" script phase declares no inputs
so Xcode's incremental build skips re-running it after `EXIFTOOL_REQUIRED_VERSION` changes —
harmless for the workspace build Chris actually uses, but worth a Clean Build Folder if anyone
ever builds via the bare `.xcodeproj`.

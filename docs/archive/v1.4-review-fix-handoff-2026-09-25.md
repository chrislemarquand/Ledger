# Final-review fixes — developer handoff

These changes build on the existing uncommitted v1.4 fixes. They address the
remaining failures from the final verification, not the entire original audit.
No commits were created and unrelated working-tree changes were preserved.

## Changes made

- **#1 / #3 ownership:** `startLoadingFiles(for:)` owns the actual load task,
  generation, and loading-state cleanup. UI actions call it directly;
  sequential workflows call `loadFiles(for:)`, which awaits the same owned
  task and forwards caller cancellation. This includes the previously missed
  metadata-refresh fallback and Apply/Restore reloads. Replacements cancel
  their predecessors; only the current generation clears the spinner/task.
  Source loss and nil/device selection invalidate and cancel the pending load.
  Reload-dependent metadata refresh and restored selection honor unsuccessful
  completion. Apply preserves failed edits while recording actual reload success.
- **#3 enumeration:** cancellation is checked before directory enumeration and
  between per-file queries. Existing cancellation forwarding for enumeration
  and attribute hydration remains. A filesystem call already in progress
  cannot be interrupted; hydration still checks between 96-file batches.
- **#4:** both date-rendering paths now use only the captured session dictionary.
  Missing dates stay unavailable; there is no synchronous fallback read.
  Date capture has task ownership and a request ID. New requests cancel old
  captures; dismissal invalidates and cancels capture, including native sheet
  dismissal and successful staging. An older same-file request cannot overwrite
  a newer sheet. The capture loop cooperates with cancellation.
- **#7:** polling tasks and request IDs are owned per URL and cancelled on stop
  and completion. A suspended old poll cannot expire a restarted request for
  the same URL. Small injected provider/state/clock/sleep closures permit
  hermetic timeout and restart tests while retaining real API defaults.
- **Broker test hardening:** overflow setup now waits for evidence of 48 denied
  requests and 200 queued requests. Cancellation testing waits for real permit
  occupancy and fresh-request queuing. Same-key testing waits for old/replacement
  work to start and old cleanup to finish; task completion waits are bounded.
  The duplicate non-execution assertion uses a bounded inverted expectation.
  Production permit accounting was not changed.

## Regression coverage

Added tests for superseded loading-state ownership, load invalidation, cancelled
enumeration, missing-date snapshots, overlapping date requests, dismissal during
capture, accepted-but-stalled cloud downloads, and same-URL tracking restart.
Updated the older filesystem-date test to open a real captured session instead
of relying on live reads from a manually constructed session.

Debug app-unit validation command:

```sh
xcodebuild test -project Ledger.xcodeproj -scheme Ledger \
  -configuration Debug -destination 'platform=macOS' \
  -only-testing:LedgerTests -parallel-testing-enabled NO
```

Result: **218 tests reported, zero failures, one skip**. The skip is the existing
mounted-volume test because no removable/ejectable volume is available.
The build emits AppIntents extraction notices; do not describe this as a
warning-free build. `git diff --check` is clean.
